# 真实运行记录

环境：Windows / Python 3.11.9 / langgraph 1.2.15 / mcp 1.30.0
传输：`streamable-http`（`https://mcp.amap.com/mcp`）
模型：`gemini-3-flash-preview`（aihubmix）

## 运行 1：北京 3 天（首次真机）

```cmd
python -m app.cli --city 北京 --days 3 --start 2026-11-01 --end 2026-11-03
```

- 耗时 **43.4 秒**，退出码 0
- 高德 MCP 连接成功，**15 个工具**
- 工具返回：景点 3464 字符 / 天气 885 字符 / 酒店 3601 字符
- 生成 3 天行程，预算 **1265 元**（门票 215 + 住宿 600 + 餐饮 330 + 交通 120，分项自洽）

发现两个质量问题：

1. 第 3 天出现 `住宿：无（0 元/晚）`——模型用「无」表示当天不住宿，渲染层没过滤
2. 同一天把国子监、圆明园西洋楼、古观象台排在一起，三者相距十几公里

## 修正

- `cli.to_markdown`：酒店名为 `无 / None / null / -` 时不输出住宿行
- 提示词：每天景点必须地理集中（经纬度相差 ≤ 0.1 度）；不住宿时 `hotel` 留空，不要写「无」
- 两条新测试钉住渲染行为（`TestMarkdownRendering`）

## stdio 传输的记录

`--transport stdio` 在本机（受限环境）报：

```
PermissionError: [WinError 5] 拒绝访问。   ← asyncio/windows_utils.py: pipe()
```

原因是 Windows 上 asyncio 建子进程要开**命名管道**，受限环境禁止。服务器本身是好的：
用 `subprocess.Popen`（匿名管道）手工握手时，`initialize` 返回
`mcp-server/amap-maps 0.1.0`，`tools/list` 返回 12 个工具。

现在这种失败会转成一句可读的提示：

```
AmapToolError: stdio 无法启动子进程（WinError 5：命名管道被限制）。
当前环境请改用默认的 --transport streamable-http。
```

在普通命令行里应当可以正常跑 stdio（未在此环境验证）。

## 两种传输的差异（实测）

| | streamable-http | stdio（npx 包 0.0.8） |
|---|---|---|
| 工具数 | **15** | **12** |
| 差异 | 多 `maps_schema_personal_map` / `maps_schema_navi` / `maps_schema_take_taxi` | 无这三个 |
| 命名 | `maps_direction_bicycling` | `maps_bicycling` |
| 依赖 | 无（纯 HTTP） | 需 Node + npm 拉包 |

本项目的三个工具（`maps_text_search` / `maps_weather`）两边同名，所以切换传输不用改代码。
